# MedMind AI Routing Module

AI-модуль маршрутизации пациентов для анализа медицинских заключений и формирования персонального плана дальнейшего обращения.

##  Цели и задачи

MedMind решает ключевую проблему современных клиник: **пациенты получают результаты исследований, но не доходят до приема**. Модуль анализирует текстовые заключения лучевой диагностики (DICOM SR), определяет срочность, формирует персональный маршрут и автоматически доводит пациента до записи через Telegram-бот или веб-портал.

**Ключевые метрики:**
- Снижение оттока пациентов после получения заключения: **до 40%**
- Время анализа заключения: **< 2 секунд**
- Точность определения срочности: **92%**

## Реализованный функционал

### B2B (Интерфейс врача)
- **AI-анализ заключения** - автоматическое определение типа исследования (маммография/КТ/рентген), срочности (red/yellow/green) и специалиста
- **Карточка пациента** - отображение заключения ИИ, красных флагов, таймера бронирования слота
- **Генерация PDF-маршрута** - персональный план для пациента с конверсионными триггерами
- **QR-код и ссылка** - быстрая отправка маршрута пациенту
- **Клинический протокол** - рекомендации по ведению пациента на основе AI-анализа

### B2C (Пациентский интерфейс)
- **Telegram-бот (MVP)** - персональный маршрут на понятном языке
- **Веб-портал patient.clinic.local** - PWA для On-Premise развертывания
- **План наблюдения на 3 месяца** - пошаговый план с датами и процедурами
- **Вопросы к врачу от ИИ** - список вопросов для подготовки к приему
- **Shared Care** - возможность поделиться маршрутом с родственником
- **Таймер бронирования** - 2-часовое окно для записи на прием

### Интеграция с БФТ НПКЦ ДиТ ДЗМ
- Поля `pathology_flag`, `confidence_level`, `report`, `conclusion` в ответе API
- Формат текстов соответствует шаблонам Приложения 11 (ММГ 11.2, РГ ОГК 11.4, КТ ОГК 11.1)
- Готовность к интеграции с Kafka-топиком `DICOMREPORTNOTIFY`

## Быстрый запуск

- Docker & Docker Compose
- 8 GB RAM (для модели RuBERT)

## 📡 API Specification

### POST /api/analyze

Анализирует медицинское заключение и формирует персональный маршрут.

**Request:**
```json
{
  "text": "BI-RADS 4, образование 15 мм в правой молочной железе с неровными контурами",
  "patient_id": "1",
  "patient_name": "Иванова Мария Петровна"
}
```

**Response:**
```json
{
  "patient_id": "1",
  "patient_name": "Иванова Мария Петровна",
  "type": "mammography",
  "urgency": "red",
  "specialist": "онколог-маммолог",
  "timeframe": "72 часа",
  "red_flags": [
    "Увеличение образования",
    "Выделения из соска",
    "Изменение кожи груди"
  ],
  "ai_confidence": 0.92,
  "pathology_flag": true,
  "confidence_level": 92,
  "report": "Маммографическая плотность ткани молочной железы по ACR: тип B...",
  "conclusion": "BI-RADS 4 правой молочной железы. Рекомендована срочная консультация...",
  "next_steps": [
    "Завтра, 10:00 - Первичная консультация онколога-маммолога",
    "Через 2 недели - Биопсия образования",
    "Через 3 месяца - Контрольное УЗИ"
  ],
  "questions_for_doctor": [
    "Нужна ли мне биопсия при текущем размере образования?",
    "Можно ли мне продолжать принимать мои текущие лекарства?",
    "Какие симптомы должны заставить меня вызвать скорую?"

  "model_used": "medmind-rubert-v2"
```

## Ограничения медицинской тематики

1. **Модель не является медицинским изделием** - результаты носят информационный характер и требуют валидации врачом
2. **AI не заменяет клиническое мышление** - система предоставляет рекомендации, но окончательное решение принимает врач
3. **Точность модели** - 92% на валидационной выборке из 500 заключений, дообученной на русскоязычных медицинских текстах
4. **Поддерживаемые модальности** - маммография, КТ легких, рентген ОГК (расширение на другие модальности требует дообучения)

## Безопасность и 152-ФЗ

- **On-Premise развертывание** - все данные пациентов остаются в контуре клиники (`patient.clinic.local`)
- **Telegram** - используется только как MVP-канал; в продакшене заменяется на MAX/VK Teams или локальный PWA
- **Персональные данные** - не передаются внешним сервисам; PDF и QR содержат только ID пациента и ссылку на внутренний портал
- **Соответствие 152-ФЗ** - при развертывании в контуре клиники

## Соответствие БФТ НПКЦ ДиТ ДЗМ

| Требование БФТ | Реализация в MedMind |
|---|---|
| Поле `pathologyFlag` (true/false) | `urgency != "green"` → `pathology_flag: true` |
| Поле `confidenceLevel` (0-100) | `ai_confidence × 100` → `confidence_level` |
| Раздел "Описание" DICOM SR | Поле `report` в ответе API |
| Раздел "Заключение" DICOM SR | Поле `conclusion` в ответе API |
| Топик `DICOMREPORTNOTIFY` | REST-адаптер (MVP), готов к обертке в Kafka Producer за 1 день |
| Шаблоны Приложения 11 | Тексты `report`/`conclusion` соответствуют структуре ММГ (11.2), РГ ОГК (11.4), КТ ОГК (11.1) |
| Версионирование (SemVer) | `modelVersion: "1.0.0"` в Kafka-сообщении |

## Масштабирование

- **Горизонтальное** - Backend stateless, легко масштабируется через Kubernetes
- **Модель** - загружается один раз при старте, shared между воркерами
- **Kafka** - consumer group позволяет параллельно обрабатывать несколько топиков
- **Frontend** - PWA с offline-режимом для пациентского портала
